# 开荒：目录、入口、章程、Wiki

开荒的目标不是「多写几份文档」，而是让**下一个接手的人 / agent 不用先读一遍代码**。只建四个落点，每个都要能被脚本对账：

| 落点 | 回答什么 | 对账 |
|---|---|---|
| `keel/structure.json` | 顶层目录各管什么 | `DIR-01` 登记了却不存在 = error；`DIR-02` 存在却没登记 = warn |
| `keel/project.json` | 目标、范围外、里程碑出口 | `PRJ-01` 必填字段缺失 = error；`PRJ-02` 里程碑缺出口 = warn |
| `AGENTS.md` | 新来的 agent 先读哪里 | 人工：≤60 行，只做路由 |
| `docs/wiki/*.md` | 代码地图 | `WIKI-01/02/03` 清单、漏登记、引用失效 |

## 第 1 步：登记目录（10 分钟）

拷 `templates/structure.json` 到 `keel/`，只改两处：

1. `dirs` 只写**顶层目录**与职责，不抄文件树。文件树一定会过期，顶层职责几个月才变一次。
2. `ignore` 只放生成物与依赖（`node_modules`、`dist`、`coverage`），**不要用它藏真实目录**——藏进去等于关掉检查。

写法要求：一个目录一句职责，用「管什么」的口吻，不写「存放相关文件」这种等于没说的话。

```jsonc
{ "path": "src", "purpose": "应用源码；页面只组合组件，不直连数据层", "layer": "app" }
```

`layer` 是给人和 agent 看的共同语言（`app` / `docs` / `console` / `infra`），不必和代码分层一一对应。

## 第 2 步：写 AGENTS.md（10 分钟）

拷 `templates/AGENTS.md` 到项目根。**上限 60 行，只做路由**：

- 列出「开工前按顺序读哪三个文件」，不复制它们的内容。
- 列出五条硬约定（改内容只改真相源、组件先登记、Wiki 先登记、新目录先登记、有第二步就是管道断了）。
- 列出提交前两条命令。
- 列出「不要做」：不建文档站、不做模式开关、不整目录覆盖升级。

`CLAUDE.md` / `GEMINI.md` 只写一行 `@AGENTS.md`，别再写第二份内容——多一份就多一处过期。

## 第 3 步：写项目章程（10 分钟）

拷 `templates/project.json` 到 `keel/`：

- `oneLiner` 写「给谁解决什么问题」，一句话。
- `goals` 写**可验收的结果**，不写动作（「新人只看 wiki 能改对第一个需求」而不是「完善文档」）。
- `outOfScope` 必须非空。写不出「不做什么」，说明范围还没想清楚。
- 每个里程碑必须有 `exit`（出口条件），且是别人能复核的句子，例如「`console-check --strict` 退出码 0」。

`PRJ-02` 只查字段在不在；出口条件是否真的可验收是人的判断，机器不假装能判。

## 第 4 步：Wiki 五篇（各 30 分钟）

把 `templates/wiki/` 拷到 `docs/wiki/`，再按真实项目改写。顺序固定：总览 → 架构 → 后端 → 前端 → 运行。

判据只有一句：**新人只靠这五篇，能不能把项目跑起来并改对第一个需求。** 不能，说明 `operations.md` 写得太省。

贴真实实现用引用式内联（语法见 `references/wiki.md` 的「引用式内联」一节），**不要手粘贴**——手粘贴的代码过期了没有任何东西会报错。

## 第 5 步：把开荒结果接进门禁

```bash
node keel/console-check.mjs --strict
```

- `DIR-01` / `PRJ-01` 是 error：登记表指向不存在的目录、章程缺必填字段，都会挡 CI。
- `DIR-02` / `PRJ-02` 是 warn：多了没登记的目录、里程碑缺出口条件，需要人判断，不该让 CI 替你决定。

## 和 PM 类技能的分工

如果项目里已经有 `.ai/` 契约目录（HANDOFF / TASKS / DECISIONS / ROADMAP 等），**不要重复建**：

- `keel/` 管**事实**：目录职责、项目目标与里程碑出口、规则、组件、Wiki 清单。
- `.ai/` 管**流程与状态**：谁在做、到哪了、为什么这么定、风险是什么。
- `AGENTS.md` 是唯一入口：先指 `.ai/HANDOFF.md`（如果有），再指 `keel/README.md`，最后指 `docs/wiki/README.md`。

两套都建的唯一后果是两份互相矛盾的「当前状态」。没有 PM 系统时，`project.json` 只承担最低限度：目标、范围外、里程碑出口——够评审和发版用，不假装是任务板。

## 验收

- [ ] `structure.json` 里的每个目录都真实存在，每个都有说得清职责的 `purpose`
- [ ] 新增一个顶层目录但不登记，`DIR-02` 报 warn 并点名它
- [ ] `AGENTS.md` ≤60 行，且不含任何可执行的结构细节（只有路由与命令）
- [ ] `project.json` 的 `outOfScope` 非空，每个里程碑都有可复核的 `exit`
- [ ] `docs/wiki/` 五篇齐备，`keel/wiki.json` 清单与目录一致
- [ ] 新人只读 `AGENTS.md` → `keel/README.md` → `docs/wiki/` 能开始干活
