# 组件页（统一化管理）

## 目标不是"有个组件库页面"

是这三件事同时成立：

1. **一个交互只有一份实现** —— 想改，改一次。
2. **样式看得见真实样子** —— 不是截图、不是描述，是组件本身渲染出来的。
3. **哪些在用、哪些没人用、哪些还没登记** —— 一眼能列出来，能直接下架。

第 3 条是多数项目缺的：组件清单人人都能写，但没人知道 30 个组件里有 12 个已经没人引用了。

## 分层（引用方向单向）

| 层 | 放什么 | 谁能引用它 |
|---|---|---|
| `base` 基础控件 | UI 库组件经统一出口再导出 | 所有层 |
| `ui` 自研语义件 | 承载项目语义的最小构件（标签、状态、容器、轻量按钮） | patterns / 业务视图 |
| `patterns` 跨域结构件 | 两个以上业务域共用的页面骨架、表单、卡片 | 业务视图 |
| `visualization` 可视化件 | 图表渲染、画布、类型切换 | 业务视图 |

铁律：**上层可复用下层，下层不得反向依赖业务页面。** 业务视图（`views`）只能从 `ui` / `patterns` / `visualization` 取件，**不许直接 import UI 库**——UI 库是实现细节，一旦直连，换库时要改遍全站。

## 注册条目

```jsonc
{
  "key": "entity-card",                  // 稳定标识
  "name": "资源实体卡",                    // 中文名（页面主标题）
  "exportName": "EntityCard",            // 导出名
  "layer": "patterns",
  "category": "数据展示",                  // 按钮/表单/选择/展示/反馈/数据展示/弹层/布局/画布/图表
  "path": "src/components/patterns/EntityCard.vue",   // 相对项目根，用于校验存在性 + 扫描引用
  "summary": "资源列表的唯一卡片形态：图标+名称+状态 / 标签行 / 元数据 / 悬停操作条。",
  "variants": ["selected", "unavailable", "leading", "icon", "actions"],
  "demo": "auto",                        // "auto" = 找同名 .demo.*；null = 明确无预览
  "matrix": [                            // 变体×状态矩阵，页面逐格渲染真实组件
    { "label": "默认", "props": {} },
    { "label": "选中", "props": { "selected": true } },
    { "label": "不可用", "props": { "unavailable": true } }
  ],
  "note": "不可用态整体降透明并用标签说明原因，不要只用 tooltip。",   // 踩坑点，可选
  "deprecated": false
}
```

`summary` 要写成**"唯一实现"的句式**，不要写功能罗列。写"资源列表的唯一卡片形态"，别人才知道不该另造一个；写"一个卡片，支持图标和状态"，别人一定会再造一个。

## 样式预览：三档，禁止第四档

| 档位 | 做法 | 适用 |
|---|---|---|
| A 真实预览 | 组件自带 `Xxx.demo.vue` / `Xxx.demo.tsx`，与实现**同目录同名** | 所有可独立渲染的组件 |
| B 说明占位 | 声明 `"demo": null` 并写明原因（需要真实数据/整页上下文/画布） | 依赖上下文的组件 |
| C 不登记预览 | —— | 不存在这一档 |

**关键设计：demo 与实现同目录同名，扫描器自动发现。**

```
src/components/patterns/
├── EntityCard.vue
└── EntityCard.demo.vue      ← 页面自动渲染它，注册表里什么都不用写
```

为什么必须这样，而不是在一个预览文件里 `v-if` 一个个列举：

> 参考项目踩过的坑：预览写成一个巨型 `v-if/v-else-if(props.entry.key === 'button')` 的 switch。结果是——**新增组件必须回去改预览文件**，不改就显示"暂无预览"，而没人记得改。这直接把"新增在此注册即可"变成了"注册 + 改预览"两步，第二步永远会漏。

用同目录 demo 文件后，新增组件 = 加组件 + 加 demo + 写一条注册表，**不需要动任何已存在的文件**。这是"可扩展"和"必然失败"的分界线。

demo 文件的三条要求：

- 用**真实组件 + 真实令牌**渲染，不写假样式（假样式比没预览更糟，会误导）。
- 覆盖该组件的关键变体（变体多时给一个可切换的小工具条）。
- 不引真实 API、不依赖路由，纯 props 驱动。

## 样式矩阵：变体 × 状态

只渲染一个默认态，等于只展示了这个组件的二十分之一。**开发者来组件页是为了看"我要的那个样子长什么样"**，所以每个组件要给矩阵。

矩阵由注册表的 `matrix` 字段声明，页面逐格渲染真实组件：

```jsonc
"matrix": [
  { "label": "主要", "props": { "type": "primary" } },
  { "label": "次要", "props": { "type": "secondary" } },
  { "label": "危险", "props": { "type": "danger" } },
  { "label": "禁用", "props": { "disabled": true } }
]
```

三条硬要求：

**① 每一格都标出生效的 props。** 「哪个 props 产生这个样式」才是开发者要的信息，光看图他一眼看不出 `type` 还是 `variant`。标签可复制。

**② 只摆 props 能表达的状态，不摆拍 hover / focus。** 悬停态必须靠真实交互看——摆出来的悬停是假的，按下去没反应。`disabled` / `loading` / `selected` 这类由 props 决定的才进矩阵。这条界限写清楚，是为了不让页面变成一堆截图。

**③ 没有 `matrix` 时退化为单格默认渲染，不要空白。** 空白会让人以为组件坏了。没写 matrix 的组件在卡片上标「未声明变体」——这是待补项，不是正常态。

什么时候可以不做矩阵：组件本身没有变体（如纯容器 `GridCanvas`），此时 `matrix` 写一格并在 `note` 里说明"无变体，仅整页上下文"。**「没变体」和「懒得写」要在注册表里区分开。**

## 使用 / 未使用检测

静态扫描，不需要运行时埋点。

**算法**

```
候选文件 = 源码目录下 *.vue|*.tsx|*.jsx|*.ts|*.js
排除    = 组件自身 + 同名 .demo.* + *.stories.* + index.* 出口文件
        + keel/ 目录（文档页自己不算使用）+ 测试文件

命中判定（任一即算被引用）
  ① 路径导入： from '.../EntityCard'
  ② 具名导入： import { EntityCard } from '.../patterns'
  ③ 手动补充：注册表 "manualUsage": ["docs/example.md"] 或动态注册处

usage = 命中的文件数（不是出现次数，次数会随页面改动噪音过大）
```

**三态呈现**

| 状态 | 颜色 | 判定 | 页面动作 |
|---|---|---|---|
| 在用 | 常规/绿 | `usage > 0` | 显示"被 N 处引用" |
| 未登记 | 黄 | 目录里有、注册表没有 | 顶部告警条列出文件清单 |
| 未使用 | 灰 | `usage === 0` 且已登记 | 收进"待下架"分区，标 `deprecated` 候选 |

**未使用不等于可以删。** 动态 `import(\`./${name}\`)`、字符串注册、跨仓库引用都会漏扫。所以：

- 未使用 → 标记为"候选下架"，观察一个迭代周期。
- 要下架，先标 `deprecated: true`（页面打灰并提示替代组件），再删。
- 不提供"一键删除"按钮。这种按钮第一次用就会删掉还在用的东西。

## 统一化门禁（可脚本化）

| 编号 | 门禁 | 检测方式 |
|---|---|---|
| C-01 | 业务视图不直连 UI 库 | grep `views/` 下的 `import ... from '<ui-lib>'` |
| C-02 | 跨域组件必须上移 | grep feature A 目录引用 feature B 的私有组件 |
| C-03 | 同一交互只有一份实现 | 同名/同职责组件出现两次 → 人工评审项（脚本只提示高相似度文件名与 props） |
| C-04 | 视图文件不超过 250 行 | 行数统计，超了记 warning 不阻断 |
| C-05 | 新增共享组件先登记 | 目录扫描 vs 注册表，未登记即报错 |

C-05 是四件套里唯一"阻断式"的门禁。它必须报错，因为这一条守不住，整个组件页就退化成过期清单。

## 新增一个组件：五步

1. 判断是否真的需要新组件（先用搜索看有没有同类：按 `summary` 搜，不按名字搜）。
2. 决定放哪一层（跨两个域以上 → `patterns`；只承载语义 → `ui`）。
3. 写实现，并在**同目录**写 `Xxx.demo.vue`。
4. 在 `components.json` 加一条，`summary` 用"唯一实现"句式。
5. 跑体检脚本，未登记数必须归零。

**第 4 步不需要改任何其他文件** —— 这是这套设计是否成立的自检标准。

## 页面骨架

```
Hero：已登记 / 共享层总数 / 覆盖率 / 未登记（四个指标）
├── 告警条（字段层，按边界决定给谁看）：N 个组件未登记，列出文件
├── 01 分层体系：四张层卡（可点选筛选，说明引用方向）
├── 02 组件目录：层筛选 + 分类筛选 + 关键词 → 卡片网格
│      卡片 = 渲染区（真实组件，可选尺寸）/ 变体×状态矩阵（每格标 props）
│           + 中文名 + 导出名 + 层标签 + 分类 / 用途 / 变体 / 路径（可复制）/ 引用数
└── 03 待下架（可折叠）：未使用组件清单
```

卡片本身有一个可拷走的骨架：`templates/ComponentCard.skeleton.vue`。它只负责「怎么把注册表一条渲染成卡片」，样式全用令牌，不绑组件库——换库时改的是令牌，不是卡片。

不做：不做树形侧边导航（层 + 分类两个筛选够了）；不做组件详情弹窗（卡片信息已足够，详情去看源码）。

## 验收

- [ ] 新增一个组件 + demo + 一条注册，**不修改任何已存在的文件**，页面就能展示它
- [ ] 目录里塞一个未登记的组件，刷新后告警条出现，点名该文件
- [ ] 删掉某组件的所有引用，它自动进入"待下架"
- [ ] 每个 `demo` 非 null 的组件，预览区渲染的是真实组件（改组件样式，预览同步变）
- [ ] 声明了 `matrix` 的组件，每一格都能看到对应 props 生效后的样子，且标签能复制
- [ ] 页面上没有任何一张组件截图——是截图就说明它已经过期了
- [ ] 对外产物里，告警条与源码路径全部不出现（不是隐藏，是不存在或拿不到）
- [ ] 覆盖率指标 = 已登记共享组件 / 实际共享组件，且脚本能复算出同一个数
