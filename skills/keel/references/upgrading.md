# 升级与迁移

## 一句话

技能本体可以覆盖安装，**你项目里的 `keel/` 不会跟着变**——它是拷贝制。所以这里只干两件事：告诉你有新版、告诉你怎么改。

## 为什么是拷贝制

- **模板只是起点。** 你会改 `srcDir`、加自己的规则、把组件列表填成你的项目事实。整目录覆盖等于把这些全冲掉。
- **千人千面。** 不同项目的 `keel/` 结构本来就不同，工具无法安全地猜哪段该合并。
- 于是分工：**技能随版本走，`keel/` 随项目走**，两者用版本号对账。

## 怎么知道有新版

```bash
node keel/console-check.mjs
```

`VER-01` 那一行给三种状态：

| 输出 | 含义 |
|---|---|
| `ok 模板版本 2.1.0（最新）` | 对齐了，不用管 |
| `warn 模板版本 2.0.0，当前技能 2.1.0` | 有更新，看下面「版本区间」对应那一节 |
| `warn 未声明模板版本` | 老文件没有这个字段，补 `"keelVersion"` 即可 |

它是 **warn 不是 error**：升级提醒不该让 CI 变红。红的东西会被整体忽略，包括真正该看的那些。

版本号写在 `keel/console.config.json`：

```json
{
  "version": 1,
  "keelVersion": "2.1.0"
}
```

`version` 是这个文件自己的结构版本，`keelVersion` 是「这份模板来自哪个技能版本」。两个别混。

## 升级技能本体

```bash
npx skills add Chaierss/keel -g          # 覆盖安装
node keel/console-check.mjs --version    # 确认脚本版本
```

Trae / WorkBuddy 走各自的上传入口，传新 zip 覆盖即可。

## 版本区间

### 2.0.x → 2.1.0（纯新增）

不改任何已有字段的语义，老文件原样能跑。想用上新能力再做下面几件：

| 变化 | 你要做什么 |
|---|---|
| `rules.json` 新增 `terms` 数组 | 不加也能过体检。加的话每条要 `name` + `definition` + `avoid` |
| 默认库变厚（15 规则 / 4 形态 / 8 术语） | 别整份覆盖。挑你要的条目拷进自己的 `rules.json`，`source` 换成真实路径 |
| 组件注册表新增 `matrix` | 给有变体的组件加；不写则退化为单格渲染，卡片会标「未声明变体」 |
| Wiki 支持 `<!-- keel:code 路径 起-止 -->` | 把既有的手粘贴代码换成引用。`WIKI-03` 会校验行号，先跑一遍再提交 |
| 新增 `templates/ComponentCard.skeleton.vue` | 可选。用得上就拷，注意改里面的 glob 前缀 |

### 1.0.x → 2.0.0（破坏性）

| 变化 | 你要做什么 |
|---|---|
| `templates/devMode.ts` 删除 | 删掉 `keel/devMode.ts` 与所有 `isDev()` 调用，按 `visibility.md` 的三层重新落 |
| `references/modes.md` → `visibility.md` | 改名 + 重写，不影响你的运行代码，只影响你读文档的路径 |
| `console-check` 的 `MODE-01` → `CFG-01` | 若 CI 里按 ID 过滤输出，改这个 ID。检查逻辑与退出码语义未变 |
| `console.config.json` 新增 `keelVersion` | 补 `"keelVersion": "2.1.0"` |
| 页面里的模式角标 / 切换开关 | 删掉。迁移对照表在 `visibility.md` 末节 |

### 1.0.0 → 1.0.1（无破坏）

文档与图片改动，脚本行为一行未改。补一个 `keelVersion` 就算完。

## 三种升级姿势

**只增不覆盖（推荐）** —— 新模板拷成 `Xxx.new`，逐段比对，只搬你需要的部分。多花十分钟，保住你自己写的东西。

**整目录覆盖** —— 只有一种情况可以这么干：你的 `keel/` 里全是原样模板，一条没改。覆盖前先 `git status` 看一眼。

**不动** —— 合法选项。模板是起点不是标准答案；老版本能跑就不用升，`VER-01` 会一直提醒，但不会拦你。

## 别做的事

- ❌ **别让脚本自动改你的 `rules.json` / `components.json`** —— 那是项目事实，工具无权推断该留哪条、删哪条。
- ❌ **别为了消掉 `VER-01` 把版本号改成最新却不实际迁移** —— 体检从此失效，等于自己把告警关了。
- ❌ **别只看最新一节** —— 跨多个大版本时，中间每一节的破坏性变更都要过一遍，它们不会自动合并。
